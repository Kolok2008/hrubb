## 1. Общая архитектура приложения

Приложение построено по принципу **чёткого разделения ответственности**: весь игровой цикл, рендеринг WebGL, физика и звук изолированы внутри императивного класса `GameEngine`, а React отвечает исключительно за декларативный HUD, меню, панели и оверлеи, получая иммутабельные снимки `HudSnapshot`.

└──────────────────┬───────────────────────────────────▲──────────────────┘
                   │ Команды (startGame, sellAll,      │ Снимки HudSnapshot
                   │ toggleFlashlight, drinkTea, ...)  │ + ToastMessage

## 2. Жизненный цикл кадра и защита от Software-WebGL

Для предотвращения зависаний в браузерах без аппаратного ускорения (например, headless-окружения, виртуальные машины, `SwiftShader` / `llvmpipe`) при старте выполняется `detectSoftwareGl()`.

```text
  requestAnimationFrame(loop)
         │
         ▼
  ┌──────────────────────────┐
  │ Вычисление dt (clamp)    │
  │ Обновление времени дня   │ (07:00 → 21:00 за 18 реальных минут)
  └────────────┬─────────────┘
               ▼
  ┌──────────────────────────────────────────────────────────┐
  │ Шаг симуляции (только в режиме 'play'):                  │
  │  1. PlayerController.update() → SurfaceDetector.sample() │
  │  2. LivelyMushroomSystem.update() (акустика + прыжки)    │
  │  3. WolfManager.update() (погоня / отвлечение на бросок) │
  │  4. PhysicsWorld.update() (броски, ящики, 420 частиц)    │
  │  5. AtmosphereSystem.update() (костёр, дождь, лучи)      │
  │  6. Сушилка (прогресс 0..1), фонарик, дебаффы            │
  │  7. ViewModelController.update() (пружины рук/ножа)      │
  └────────────┬─────────────────────────────────────────────┘
               ▼
  ┌──────────────────────────────────────────────────────────┐
  │ Ветвление рендера:                                       │
  │  • Аппаратный GPU  ──► EffectComposer                    │
  │       (RenderPass → UnrealBloomPass → AUTUMN_GRADE →     │
  │        OutputPass) + тени PCFSoftShadowMap               │
  │  • Software WebGL  ──► Прямой renderer.render() без      │
  │       bloom/теней + адаптивный троттлинг (afterDraw)     │
  └────────────┬─────────────────────────────────────────────┘
               ▼
  Троттлированный emitHud() → React обновляет DOM по необходимости
```

- **Защита `detectSoftwareGl()`**: проверяет строку `UNMASKED_RENDERER_WEBGL` на совпадение с `/SwiftShader|llvmpipe|softpipe|Software|Basic Render/i`. При срабатывании пропускает `renderer.compile()`, отключает тяжёлые карты теней и пост-обработку bloom и ограничивает частоту отрисовки, сохраняя отзывчивость интерфейса.
- **Восстановление контекста**: подключены обработчики `webglcontextlost` / `webglcontextrestored` с уведомлением пользователя.

## 3. Конечный автомат «живых» грибов и ИИ волков

### Конечный автомат `LivelyMushroomSystem`

Каждый «живой» гриб управляется структурой `LivelyAgent` с явным набором состояний и физическими каналами (`vx`, `vz`, `posY`, `vy`, `HOP_GRAVITY = -14.2`, плюс GSAP-каналы `sx/sy/sz/spinY/sinkY/rootScale/wiggle`):

```text
                       Шум шагов > порога
   ┌────────┐ ───────────────────────────────────► ┌─────────┐
   │  idle  │ ◄─────────────────────────────────── │  alert  │
   └────────┘   Игрок присел (C) / утих            │ (дрожь, │
        │                                          │  писк)  │
        │ Резкий шум / удар / подход стоя          └────┬────┘
        └───────────────────────┐                       │ Шум растёт
                                ▼                       ▼
                          ┌───────────┐          ┌────────────┐
                          │ startled  │─────────►│  fleeing   │
                          │(выпускает │          │(баллистика │
                          │ корешки)  │          │ прыжков +  │
                          └───────────┘          │ след спор) │
                                                 └─────┬──────┘
                                                       │ Прошло 5–10 с
                                                       ▼
┌─────────────────────┐    Зарылся (0.85 с)    ┌───────────────┐
│ Свежая куча листьев │◄───────────────────────│ seeking_cover │
│  • Присед (C) →     │   ┌───────────────┐    │ (ищет дерево  │
│    замер, можно     │◄──│   burrowing   │◄───│  или куст)    │
│    срезать          │   │ (можно успеть │    └───────────────┘
│  • Стоя / камень(Q) │   │  схватить!)   │
│    → снова fleeing  │   └───────────────┘
└─────────────────────┘
```

- **Чистая естественная подача**: в `v1.0.2` убраны все наземные кольца шума и ореолы под грибами. Игрок считывает состояние по звуку (писк, топот корешков, шелест зарывания), шлейфу из пула `MAX_SPORES = 160` и анимации.
- **Ведьмины круги (`FairyRingRecord`)**: на старте дня генерируются 5–6 полян со светящимся кольцом грибов и кружащими спорами, активирующими достижение `fairy_ring` при обнаружении.

### ИИ волков (`WolfManager`)
- Патрулируют участки вдали от защищённой зоны усадьбы.
- При броске камня/ветки (`Q`) точка падения передаётся волкам — хищник переключается на расследование звука (засчитывается достижение `stone_trickster`).
- Агрессивность и дистанция обнаружения зависят от погоды (`mist` приближает волков) и события дня (`wolf_hunt`).

## 4. Генерация мира, усадьба и инстансинг

### Рельеф и процедурные текстуры (`terrain.ts`, `textures.ts`)
- Высота и нормаль земли вычисляются аналитически функциями `groundHeightAt(x, z)` и `groundNormalAt(x, z)` — все подсистемы (трава, деревья, грибы, шаги, физика, волки) опираются на единый детерминированный источник правды.
- Фактор мха (`mossFactorAt`) и расстояние до тропы (`trailDistance`) синхронизированы между вершинным/фрагментным шейдером ландшафта и `SurfaceDetector`.
- Все текстуры (кора, древесина брёвен, клетчатое одеяло кровати, тканый ковёр, карта леса на стене, вывески *«СКУПКА ГРИБОВ»*, указатели *«← ИЗБУШКА / ЧАЩА →»*) генерируются на `<canvas>` при загрузке без внешних бинарных ассетов.

### Оптимизация леса и зоны отчуждения усадьбы (`WorldBuilder.ts`)
- **Чанковый инстансинг (`ChunkInstancer`)**: деревья, стволы, кроны, кусты, папоротники и камни разбиваются по пространственным чанкам в `InstancedMesh`, что позволяет GPU эффективно выполнять frustum culling и снижает число draw calls.
- **Якоря усадьбы и защита от наложений (`isPropBlockedByCamp`)**:
  - Перед расстановкой камней, деревьев и кустов рассчитываются точные координаты ключевых точек усадьбы: избушка (`HUT_POSE`), костёр, сушилка, лавка скупщика, повозка, скамья и траектория камеры главного меню.
  - Любой природный объект, попадающий в защитный радиус любой станции (включая костёр), отбраковывается до генерации геометрии и коллайдеров.
- **Интерьер избушки**: скомпонован внутри локальной системы координат хижины с раздельными коллайдерами (`kind: 'hut' | 'furniture'`) — резная кровать, тумбочка со свечой и часами, верстак с книгой и масляной лампой, табурет, настенные полки с банками, карта в рамке, вешалка с корзиной, поленница и потолочный фонарь.

## 5. Кинематика игрока, поверхности и физика

### 6-DOF пружины и хореограф шагов (`PlayerController.ts`, `SpringSystem.ts`)
- Положение и наклон камеры/рук сглаживаются критически демпфированными пружинами (`CriticalSpring`, `Spring6DOF`) при приседании, приземлении, резких разворотах и ударах.
- **3-фазный хореограф шагов на GSAP**: каждый шаг раскладывается на фазы `heel` (касание пятки), `toe` (отталкивание носком), `debris` (шорох листьев/гравия) и `breath` (дыхание при усталости), напрямую синхронизированные с `AudioEngine` и акустическим радиусом для `LivelyMushroomSystem`.
- **Динамический FOV**: плавно расширяется при спринте и сужается при переходе в крупный план среза гриба.

### Классификатор поверхностей (`SurfaceDetector.ts`)
- Камни и галька индексируются в пространственную хэш-сетку с шагом `8 м` (`stoneGrid`) для поиска за `O(1)`.
- Порядок приоритета весов: `wood` (избушка, крыльцо, настил скупки) → `stone` (валуны, галька, крутые склоны с `normal.y < 0.89`) → `dirt` (тропа) → `moss` и `leaves` (с учётом усиления от куч листьев `leafPileBoost`).
- На границах зон возвращается основная (`primary`) и вторичная (`secondary`, вес до `0.46`) поверхность для органичного кроссфейда звука шагов.

### Физика твёрдых тел и эффектов (`PhysicsWorld.ts`)
- **Разрушаемые ящики**: `3 HP`, отлетают от импульса ножа (зависит от `knife.force`), при разрушении разлетаются на щепки и могут заспавнить свежий гриб.
- **Катящиеся брёвна и бочки**: реагируют на столкновения и удары с физическим вращением по рельефу.
- **Броски камней/веток и срубленные шляпки**: баллистическая траектория с отскоком от `groundHeightAt`, передача события удара в `AudioEngine`, `WolfManager` и `LivelyMushroomSystem`.
- **Пул частиц**: предвыделенный пул на **420 частиц** без аллокаций в игровом цикле (щепки, земля, споры, брызги удара).

## 6. Погода, освещение, фонарик и постобработка

- **Суточный цикл освещения (`updateDaylight`)**: плавно интерполирует положение солнца, цвет полусферного и направленного света, плотность и оттенок экспоненциального тумана от холодного рассвета (`07:00`) через золотой полдень к багровым сумеркам и синей ночи (`21:00`).
- **Погода (`AtmosphereSystem`)**:
  - Плавный кроссфейд между `clear`, `mist` и `rain`.
  - В `clear` активны полупрозрачные объёмные лучи солнца; в `rain` — анимированные полосы дождя вокруг игрока и множитель скрытности `0.70`; вечером появляются светлячки.
- **Двухуровневый фонарик (`L`)**:
  - Управляется флагом `flashlightOn` (активен в режиме `play`, выключается при возврате в меню/сне).
  - Без апгрейда: карманный `SpotLight` (`intensity: 15`, `distance: 24`).
  - С улучшением `lamp`: налобный прожектор (`intensity: 30`, `distance: 44`) + ближний заполняющий `PointLight` (`headLampFill`, дистанция `6 м`).
- **Постобработка (`AUTUMN_GRADE_SHADER`)**: кастомный `ShaderPass` добавляет тёплую осеннюю цветокоррекцию (`uWarm`), виньетирование (`uVignette`), деликатное плёночное зерно и радиальное размытие/покачивание (`uBlur`) при отравлении красным мухомором.

## 7. Процедурный синтез звука (Web Audio API)

Модуль `src/game/audio/AudioEngine.ts` не загружает ни одного `.mp3`/`.wav` файла — вся звуковая картина генерируется на лету из осцилляторов, буферов белого/розового шума, полосовых фильтров и огибающих:

- **Шаги**: отдельные рецепты для 5 поверхностей (`moss`, `leaves`, `stone`, `dirt`, `wood`) с поддержкой одновременного смешивания `primary` + `secondary`.
- **Окружение**: пространственный треск костра (зависит от дистанции до очага), потоки дождя, порывы ветра, пение птиц днём, крики сов в сумерках, стук дятла, далёкий вой волков.
- **Игровые эффекты**: механический щелчок фонарика (`flashlightClick`), срез ножа, очистка лезвия, удары по ящикам и волкам, звон монет, глоток горячего чая, тревожный писк/прыжки/зарывание живых грибов.
- **Музыка**: генеративный тёплый акустический эмбиент с независимым регулятором громкости в настройках.

## 8. Мост Engine ↔ React, локализация и сохранения

### Синхронизация состояния
- `GameEngine` публикует компактный объект `HudSnapshot` в React через колбэк подписки, избегая лишних ре-рендеров на 60 FPS там, где данные не изменились.
- Уведомления отправляются через очередь `ToastMessage` с цветовой семантикой (`good` / `warn` / `bad`), а разблокировка достижений отображает отдельный баннер `achievementBanner`.

### Локализация (`src/game/i18n.ts`)
- Поддерживаются два полных языка: **`ru`** (по умолчанию) и **`uk`**.
- Единый набор хелперов (`t`, `getSpeciesLoc`, `getKnifeLoc`, `getUpgradeLoc`, `getWeatherLoc`, `getEventLoc`, `getAchievementLoc`) обслуживает как React UI, так и 3D-текстуры вывесок в мире.

### Персистентность в `localStorage`

| Ключ `localStorage` | Структура | Что хранит |
| :--- | :--- | :--- |
| `hrybnyk-save-v2` | `SaveData` (`v: 1`) | День, деньги (`₴`), текущие заказы, купленные и выбранный ножи, уровни всех 7 улучшений, изученный атлас, слоты уличной сушилки (`driedRack`), открытые достижения и накопительную статистику |
| `hrybnyk-settings-v2` | `GameSettings` | Выбранный язык (`ru`/`uk`), уровень графики (`low`/`medium`/`high`), чувствительность мыши, громкость эффектов и музыки |

При загрузке `loadSave()` выполняет безопасное слияние с `createFreshSave()`, гарантируя обратную совместимость при добавлении новых полей прогресса.
